# Detección y ajustes de Fortnite

`FortniteGameService` busca manifiestos `.item` en la carpeta local Epic (máximo 128, 256 KiB cada uno), rechaza instalaciones incompletas/pendientes de validar y comprueba el ejecutable `FortniteGame/Binaries/Win64/FortniteClient-Win64-Shipping.exe`. La búsqueda alternativa usa como máximo 32 carpetas comunes, sin recorrer descendientes; el selector manual requiere el mismo ejecutable. No se modifican manifiestos ni el Launcher.

El archivo de ajustes se busca en `%LocalAppData%/FortniteGame/Saved/Config/WindowsClient/GameUserSettings.ini`, con alternativa Windows si ya existe. Tiene un límite de 512 KiB. El servicio mantiene un handle exclusivo del archivo y de sus ancestros mientras lo valida y modifica, y rechaza redirecciones, archivos con múltiples enlaces, destinos remotos, archivos ocupados o de solo lectura. La instalación y el hash revisados se comprueban nuevamente antes de escribir; el juego debe estar cerrado y se vuelve a comprobar después de respaldar.

Solo se modifican claves existentes conocidas: los grupos de calidad admitidos pasan a 0; VSync y motion blur pasan a False; mostrar FPS pasa a True. Se conservan comentarios, saltos de línea, encoding, resolución, límite FPS, renderizador, controles y claves ajenas al perfil. El archivo no se marca como solo lectura.

El journal en la subcarpeta `fortnite` de la raíz de datos (`%LocalAppData%/Silen`, o `%LocalAppData%/FlyyOptimizer` si ya existe) usa lease entre procesos y reemplazo atómico de su JSON. Antes de modificar la configuración se escriben y sincronizan a disco los bytes originales e intencionados, sus hashes y la identidad del archivo, con estado Pending. La configuración se escribe y comprueba sobre el mismo handle exclusivo: **esa escritura no es atómica ante un apagón**. Un reinicio reconoce el archivo completo por hash, o una escritura de prefijo interrumpida sobre la misma identidad a partir de los respaldos verificados. Esos estados permiten restaurar el original. Un contenido externo incompatible, una identidad distinta durante recuperación parcial o un respaldo dañado impide sobrescribirlo y conserva los respaldos. No se anuncia restauración forzada de archivos ajenos.

29 pruebas de archivos pasan con manifiestos y configuraciones en directorios propios. Cubren restauración byte por byte, encoding UTF8/UTF16/Latin1, comentarios, claves desconocidas, stale preview, juego abierto, ausencia, archivo ocupado/solo lectura, junctions/hardlinks, límites, respaldo alterado, journal con destino ajeno, redirección de AppData de Windows y recuperación de escrituras de aplicación/restauración interrumpidas. El destino del archivo se compara con el directorio físico ya abierto, manteniendo la protección de sus handles. No se editaron archivos reales de Fortnite del usuario.
